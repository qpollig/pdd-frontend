  ```ts
    ticket_id: string;

  }
  ```

### Checkout-редирект
Бэкенд-заглушка готова и делает настоящий редирект (`checkout/init` → `confirmation_url` на
рабочую mock-страницу ЮKassa, которая активирует триал и через `303` возвращает на
`BILLING_RETURN_URL?checkout=success`). На фронте нужно:
1. `RealApiClient.checkout()` — делать `window.location.href = confirmation_url`, а не
   бросать исключение.
2. Роут `/checkout/return` (или переиспользовать `/profile`) — по `?checkout=success` в URL
   опрашивать `GET /subscriptions/me` (или `/users/me`) несколько раз, пока `is_premium` не
   станет `true`, затем показать успех.
3. Изменить сам контракт `ApiClient.checkout()` / `CheckoutResult` — сейчас он рассчитан на
   мгновенный синхронный успех, а должен стать redirect-ориентированным (или `void` +
   отдельный `pollSubscription`). Это затронет разом: `ApiClient.ts`, `types.ts`,
   `MockApiClient` (+ спек), `RealApiClient.ts`, checkout-стор, `CheckoutScreen.vue`. Крупная
   задача — планировать отдельной сессией, не «заодно».
