## 1. Executive summary

Текущий фронтенд — **рабочий вертикальный скелет Phase 1**: Auth → Dashboard → Theory/Errors/Exam → Paywall → Checkout → Premium → Profile. Режимы, mock-оплата, жизни и экзаменальный таймер **реально работают** в браузере, не только в коде.

Это ещё **не единый B2C-продукт «сервис подготовки к экзамену ПДД»**. По ощущению это **внутренний кабинет ученика / LMS-прототип** с жёлтым корпоративным акцентом «Третий Рим»: много равных CTA, техтекст из ТЗ на экране, английский `trial`, UUID в статистике, footer «на стороне backend».

Главный риск до 14 сентября — не «красивость», а **три столкновения**:

1. **Обучение vs монетизация.** В mock жизни списываются в Theory (и Errors). На Free билет из 20 вопросов обрывается примерно на 10 ошибках. Ученик не может закончить базовый сценарий без Premium. Это противоречит ТЗ §4.3 и совпадает с §4.7. **OPEN QUESTION — не решать в UI без заказчика.**
2. **Conversion vs доверие.** Цена 1 ₽ → 299 ₽/мес читается. Автопродление написано несколько раз. Одновременно на витрине: «отключить в профиле, **когда появится** управление», «видео **ещё не проигрывается**», success «**mock-оплата**», юридические ссылки без URL. Для демо заказчику это выглядит как тестовая касса.
3. **IA уже перегружена.** Dashboard держит Theory / Errors / Exam / билет 1 / Premium; шапка дублирует Exam и добавляет сломанную Статистику; bottom nav говорит «Билеты», экран — «Теория». Добавлять Marathon / ads / streak **поверх этой сетки нельзя** — сначала сжать текущие входы.

Рекомендация: до 14 сентября **не делать новый визуальный язык**. Сделать узкий pass: вычистить внутренний copy, выровнять термины навигации, починить «что делать после результата», убрать Статистику из шапки или заменить заглушку, не трогать lives/5vs10/OAuth/провайдера.

## 2. Current user flow

```
/auth  (Yandex | VK mock)
  → /dashboard
       → Теория → /tickets?mode=theory → /tickets/:id?mode=theory → TicketPlayer
       → Ошибки → /tickets/errors → TicketPlayer
       → Экзамен ГИБДД → /exam-gibdd → TicketPlayer (таймер, скрытый feedback, +5)
       → Начать билет 1 → сразу плеер theory
       → Premium → /paywall → /checkout → success → /dashboard
  → /profile  (статус подписки, без отмены)
  → /statistics  (только desktop-шапка)
```

Плеер **вне** `AppLayout`: нет bottom nav / desktop header. Назад из Theory → каталог билетов; из Errors/Exam → Dashboard.

Pinia in-memory (ТЗ §2.2): reload сбрасывает сессию. Повторный вход в тот же билет **перезапускает** прогресс (`TicketPlayer` вызывает `startTicket` на mount). ResumeSessionModal нет.

## 3. Screen-by-screen audit

Оценки — по живому UI, не по наличию файла.

### Auth (`/auth`)

| Критерий | Наблюдение |
|---|---|
| Hierarchy | Заголовок «Вход» + два OAuth. Главное действие ясно (Яндекс). |
| UX | Нет логотипа/названия продукта. Пустой низ экрана. Нет ToS (в ТЗ ToS привязан к Paywall, не к Auth). |
| B2C | Выглядит как служебный login LMS, не как вход в тренажёр ПДД. |
| Priority | P2: бренд + одно предложение «зачем входить». Не блокирует Phase 1. |

### Dashboard (`/dashboard`)

| Элемент | Проблема | Почему плохо для B2C | P |
|---|---|---|---|
| Подзаголовок «Кабинет ученика» | LMS/школьный тон | Прямой ученик приходит «готовиться к экзамену», не «в кабинет» | P1 |
| Progress «0 / 800» + «виджет ТЗ §3.1» | Техтекст + счётчик не обновляется после ответов | Продукт врёт про прогресс; выглядит как недоделанный прототип | P1 |
| Билеты «0 / 40» | Не меняется после прохождения | То же | P1 |
| 4–5 равных CTA в ряд | Теория / Ошибки / Экзамен / Билет 1 / Premium | Непонятно, что делать первым; «Билет 1» дублирует Теорию | P1 |
| Premium в шапке при уже Premium | Кнопка «Premium» остаётся | Лишний вход в already-premium экран | P2 |
| Footer desktop «оплата на стороне backend» | Внутренний текст | Убивает B2C-доверие | P1 |
| Lives «Восстановление — отдельный этап» | Честный stub, но звучит как ТЗ | Ученику не сказано, *когда* жизни вернутся | P2 |

На 320px карточки занимают почти весь экран; CTA ниже сгиба; bottom nav перекрывает нижний край карточки «Билеты».

### Theory catalog (`/tickets`)

Работает: «По номерам» / «По темам», 40 карточек, bottom nav.  
Проблемы: все билеты визуально одинаковые `0/20 · A, B` (mock одного JSON); темы ведут в **тот же билет**, не в выборку темы; грамматика «1 вопросов»; bottom nav «Билеты» vs H1 «Теория». Список из 40 одинаковых карточек на mobile — высокий cognitive load (design-critic / Nielsen: recognition vs dump).

### Ticket player (Theory / Errors / Exam)

Сильные стороны: immediate feedback в theory (верно/неверно, подсветка, пояснение, без автоперехода); exam скрывает результат; таймер tabular; touch targets ответов ≥ 44px.

| Элемент | Проблема | B2C | P |
|---|---|---|---|
| Логотип 48–96px в шапке | Теснит жизни/таймер/заголовок на 320–390 | Шапка как визитка, не как инструмент сдачи | P1 |
| «3D-Видеоразбор» над вопросом | Главный CTA экрана — замок, не ответ | Ученик учится, продукт продаёт раньше вопроса. На 320 вопрос уезжает под fold | P1 |
| Стрелки QuestionNav 28×28 | < 44px | Промах на телефоне | P2 |
| «Следующие вопросы» vs «Следующий вопрос» | Два похожих действия | Путаница; Next после ответа часто ниже fold | P1 |
| Картинка «Изображение недоступно» | Битый `no_image.jpg` / путь mock | Выглядит сломанным, не «нет схемы» | P1 |
| Избранное | Кнопка есть, режима «Избранное» в навигации нет | Мёртвый контроль | P2 |
| Errors: H1 «Билет 1», finish «Завершить билет» | Сессия ошибок названа билетом | Непонятно, где пользователь | P1 |
| Exam: счётчик 20→25→30 без копирайта | +5 молча | Страх «экзамен сломался» | P1 |
| Exam: 3D и избранное на месте | Не экзаменационный UI | Подсказка/продажа во время регламента ГИБДД | P1 |
| 0 жизней | Баннер + «К экрану Premium»; RestoreLives нет | По ТЗ должны быть реклама / 24ч / Premium | OPEN + P1 |
| Result modal | Только «На главную» | Нет «ещё раз», «разобрать ошибки», «следующий билет» | P1 |
| Back без ExitConfirmModal | Выход мгновенный | Потеря экзамена без предупреждения | P1 |

## 4. Flow problems

Ответы на вопросы сессии:

1. **Нужны ли отдельно Theory / Errors / Exam на Dashboard?**  
   Да как *понятия*. Нет как *четыре одинаковые кнопки + те же пункты в nav*. Один primary («Учить билеты») + Exam как secondary + Errors как прогресс/бейдж.

2. **Понятно ли отличие режимов?**  
   Частично: подпись каталога «без ограничения времени»; экзамен показывает таймер. Errors визуально неотличимы от theory, кроме трёх вопросов.

3. **Слишком много CTA?** Да.

4. **Дублируются ли действия?** Да: Dashboard «Теория» = nav «Билеты»; «Экзамен» в dashboard + header + bottom; «Начать билет 1» = первый пункт каталога; Premium в header + dashboard + profile + player.

5. **Dashboard → Tickets логичен?** Да, если называть одинаково.

6. **Errors отдельно от каталога?** Да (другой набор вопросов). Сейчас вход спрятан на Dashboard и **отсутствует в bottom nav** — находка слабая.

7. **Exam отдельно?** Да, и так в ТЗ (§3.2, ЧПУ `/exam-gibdd`). Дублировать трижды не нужно.

8. **После билета?** Только домой. Продолжение обучения не предложено. Прогресс на главной не меняется → ощущение «я ничего не сделал».

9. **Как продолжать учиться?** Не очевидно. Каталог не помнит 0/20.

10. **Statistics лишний уровень?** Да. ТЗ §3.1 ProgressWidget на Dashboard; отдельный экран — бриф, не §3.1. Текущая реализация хуже, чем отсутствие пункта.

11. **Premium понятен?** Частично: ∞ и бейдж. Шапка всё ещё зовёт «Premium». Paywall говорит, что 3D уже доступны — в плеере замок остаётся.

12. **Free понятен?** «Free» мелким текстом; жизни 10/10 без объяснения «это ваш лимит попыток».

13. **После 0 жизней?** Переход на Paywall понятен. Нет рекламы/таймера 24ч (ТЗ 3.7). В Theory это прерывает билет на середине.

14. **Paywall vs Checkout конфликт?** Цены совпадают. Конфликт: Paywall обещает документы «на оформлении»; Checkout говорит «когда будут URL». Оба говорят, что отмена появится позже.

15. **Подписка в Profile?** Данные видны, действия нет. Copy ссылается на номер ТЗ.

Дополнительно: **перезаход в билет сбрасывает ответы**; **hard reload = logout**.

## 5. B2C positioning issues

Интерфейс ближе к **«ЛК ученика автошколы»**, чем к consumer-тренажёру:

- «Кабинет ученика», footer backend, «виджет ТЗ», «на этом этапе».
- SEO-H2 «для учеников автошкол» на Paywall (ТЗ §4.8.2 написан как SEO, попал во внутренний UI — нарушение духа §4.8.1: внутренний UI лаконичен, SEO снаружи).
- Auth без бренда; плеер с огромным логотипом.
- Inter в токенах, шрифт не подключён → системный стек. Жёлтый с логотипа — единственный характер. Не «дефолтный фиолетовый AI», но и не законченный продукт.
- Нет онбординга «что такое жизни / что такое билет / чем экзамен отличается».

Плеер (feedback, HIT-карточка, pill-кнопки) уже ближе к B2C. Оболочка Dashboard/Profile/Statistics тянет назад в LMS.

## 6. Conversion / monetization UX

Что работает:

- Оффер **3 дня / 1 ₽ → 299 ₽/мес** и бейдж ХИТ совпадают с ТЗ §3.5.
- Автопродление проговорено (даже избыточно).
- CTA «Оплатить 1 ₽» после заполнения полей.
- Already-premium не даёт купить второй раз.
- 0 жизней ведёт на Paywall.

Что ломает conversion/доверие:

| Место | Проблема | P |
|---|---|---|
| PricingCard | «отключить в профиле, когда появится управление» | P0 для боевой оплаты / внешней демо |
| Paywall | «само видео на этом этапе ещё не проигрывается» vs буллет про 3D | P0/P1 |
| Paywall mobile | Primary CTA не в первом экране | P1 |
| Checkout | Технический дисклеймер API + пустые legal URL | P1 (mock допустим, формулировка — нет) |
| Checkout success | «mock-оплата» | допустимо для внутренней сборки; **убрать перед показом заказчику** |
| Premium Paywall | «3D уже доступны» при живом замке в плеере | P1 |
| Нет промокода | ТЗ §3.5 требует; Phase 1 бриф откладывает | OPEN QUESTION |
| Нет RestoreLives | Единственный выход из 0 — купить | Соответствует жёсткому paywall, не полному ТЗ 3.7 |

## 7. Mobile / responsive

ТЗ §3.4: 375 / 768 / 1920. Проверены 320, 390, 414, 768, 1440.

| Viewport | Факт |
|---|---|
| 320 | Живёт, горизонтального скролла страницы Dashboard не видно. Шапка плеера переполнена (лого + жизни + title). Ответы под fold. BottomNav без `safe-area-inset`. |
| 390 / 414 | Основной mobile. BottomNav 4 пункта без иконок — слабо сканируется. Paywall CTA ниже fold. |
| 768 | Всё ещё BottomNav (`lg` = 1024, не 768). ТЗ: tablet — списки в 2 колонки (каталог да); nav ещё нижняя. Dashboard CTA в один ряд — тесно. |
| 1440 | Header + footer. max-w 1280. Плеер: 2 колонки media/вопрос — хорошо. Огромный логотип справа. Много пустоты. |

Адаптив **не развален**. Проблемы — плотность шапки плеера, fold CTA, touch 28px на стрелках навигации вопросов.

Web Interface Guidelines (выборочно, по коду+UI): иконка Назад имеет `aria-label`; checkout labels есть; `autocomplete=off` на карте (mock OK); modal paywall Escape есть, result modal — нет focus trap / без Escape; `prefers-reduced-motion` не найден.
